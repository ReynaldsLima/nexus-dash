<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Route Handler (/api/meta-ads/connect) | Token Meta (secret de alto valor) cruza aqui via POST body. |
| Route Handler → Meta Graph API | URL hardcoded; token enviado para validação. |
| Route Handler → Supabase Vault (service role) | Escrita do secret encriptado. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | Token Meta no transporte/log | mitigate | Token enviado via POST body (nunca query string). Nunca logado (acceptance: sem console.log(token)). Nunca retornado nas respostas. Armazenado apenas no Vault (AES-256), não em coluna texto. |
| T-03-02 | Tampering / SSRF | fetch para Meta Graph API | mitigate | URL base hardcoded (`https://graph.facebook.com/v22.0`). Somente accountId (validado por regex `act_\d+`) e token são interpolados — não a base. Sem input do usuário na host. |
| T-03-03 | Elevation of Privilege | Service role key no client | mitigate | `lib/supabase/service.ts` importa `server-only`; `route.ts` força `runtime='nodejs'`. Service client jamais bundlado no browser. |
| T-03-04 | Elevation of Privilege | Escrita não autorizada em ad_accounts | mitigate | Route Handler exige auth.getUser() + role ∈ {super_admin, tenant_admin} antes de qualquer escrita. RLS de ad_accounts bloqueia INSERT/UPDATE de não-super_admin pelo client (defesa em profundidade). |
| T-03-05 | Information Disclosure | vault_secret_id em respostas de API | mitigate | Resposta retorna apenas { success, accountId }. vault_secret_id (UUID opaco) e o secret nunca expostos ao client. |
| T-03-06 | Spoofing | RPC create_or_update_vault_secret chamado por role não autorizado | mitigate | REVOKE de anon/authenticated; GRANT apenas service_role + authenticator (PostgREST). SECURITY DEFINER. |
</threat_model>
