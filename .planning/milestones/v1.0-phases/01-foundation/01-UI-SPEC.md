## Spacing Scale

Declared values (multiples of 4, 8-point base):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline gaps |
| sm | 8px | Input internal padding, compact row gaps |
| md | 16px | Default form field spacing, card internal padding |
| lg | 24px | Section breaks inside cards, modal padding |
| xl | 32px | Card-to-card gap, page section gaps |
| 2xl | 48px | Vertical page padding on desktop |
| 3xl | 64px | Max-width centered layout margins |

Exceptions:
- Touch targets for icon-only buttons (logout, close modal): minimum 44px height — use `h-11` (44px) Tailwind class.
- Tenant switcher dropdown item height: 40px (`h-10`) for clickability.

## Typography

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|
| Body | 14px | 400 (regular) | 1.5 | `text-sm font-normal leading-relaxed` |
| Label | 14px | 600 (semibold) | 1.4 | `text-sm font-semibold leading-snug` |
| Heading | 20px | 600 (semibold) | 1.2 | `text-xl font-semibold leading-tight` |
| Display | 28px | 600 (semibold) | 1.15 | `text-2xl font-semibold leading-none` |

Notes:
- 4 sizes declared: 14 (body), 14 (label variant), 20, 28. Exactly 2 weights in use: 400 (regular) and 600 (semibold). The 28px display size provides sufficient visual hierarchy without needing a heavier weight.
- Error messages and helper text: 12px / `text-xs font-normal text-destructive` — this is form-level only, not a full typography tier.
- Monospace (Geist Mono) used exclusively for: generated temporary passwords in user-creation modal output, never for body copy.

## Color

The project is a dark-first internal analytics SaaS. Dark mode is the primary viewport for the Super Admin, who will be using it extensively. Tailwind CSS v4 + shadcn/ui CSS variables handle light/dark automatically.

| Role | Light Mode | Dark Mode | Usage | Source |
|------|-----------|-----------|-------|--------|
| Dominant (60%) | `--background: #ffffff` | `--background: #0a0a0a` | Page background, full-bleed surfaces | globals.css — already set |
| Secondary (30%) | `hsl(0 0% 96%)` / `zinc-100` | `hsl(240 3.7% 15.9%)` / `zinc-900` | Cards (`bg-card`), sidebar, nav rail, table rows | shadcn default |
| Accent (10%) | `hsl(221.2 83.2% 53.3%)` / blue-600 | `hsl(217.2 91.2% 59.8%)` / blue-500 | See reserved-for list below | default |
| Destructive | `hsl(0 72.2% 50.6%)` / red-600 | `hsl(0 62.8% 30.6%)` / red-800 | Destructive actions only (deactivate tenant, remove user) | shadcn default |
| Foreground | `#171717` | `#ededed` | Body text | globals.css — already set |
| Muted foreground | `hsl(240 3.7% 45.1%)` | `hsl(240 5% 64.9%)` | Helper text, secondary labels, placeholder text | shadcn default |
| Border | `hsl(240 5.9% 90%)` | `hsl(240 3.7% 15.9%)` | Card borders, input borders, table dividers | shadcn default |

**Accent reserved for:**
1. Primary CTA buttons: "Entrar" (login), "Salvar tenant", "Salvar usuário", "Entrar como tenant"
2. Active/selected state of the tenant switcher item
3. Focus ring on all interactive elements (auto-handled by shadcn via Radix)
4. Link text in helper copy (e.g., "Esqueci a senha" — deferred, but link color is accent when present)

**Accent is NOT used for:**
- Table column headers
- Card titles
- Inactive nav items
- Status badges (use semantic colors for active/inactive instead)

**Status badge colors (tenant active/inactive):**
- Active: `bg-emerald-500/20 text-emerald-400` (dark) / `bg-emerald-100 text-emerald-700` (light)
- Inactive: `bg-zinc-500/20 text-zinc-400` (dark) / `bg-zinc-100 text-zinc-600` (light)
- Role badge (tenant_admin, viewer): `bg-blue-500/20 text-blue-400` — muted accent, not full accent

## Layout Contract

Phase 1 has two distinct layout shells:

### 1. Public layout (unauthenticated — /login)
- Full-height centered card: `min-h-screen flex items-center justify-center bg-background`
- Login card: `w-full max-w-sm` — 384px wide
- No sidebar, no header, no nav
- **Primary visual anchor:** "Entrar" CTA button — largest interactive element in the centered card, full-width accent-colored button at the bottom of the form.

### 2. Authenticated layout (/tenants/*, /[tenant-slug]/*)
- Top header bar: `h-14` (56px), full-width, `bg-card border-b border-border`
  - Left: NEXUS-DASH wordmark (`text-sm font-semibold`)
  - Right: tenant switcher dropdown + logout button
- No sidebar in Phase 1 — sidebar scaffolded but empty; Phase 3 populates it
- Page content: `max-w-5xl mx-auto px-6 py-8` (1024px max-width, 24px horizontal padding, 32px top/bottom)
- Page title: `text-xl font-semibold` directly in page, not in header
- **Primary visual anchor (tenants overview):** Tenant table — full-width within the content area, fills the available content column and is the dominant element on the page.

### 3. Scaffolded shell (/[tenant-slug]/dashboard)
- Shows header + empty state card — no campaign data
- Empty state card centered: `flex flex-col items-center justify-center py-16`

## Interaction Contract

### Login Form
- Submit on Enter key (default form behavior)
- Disable submit button while `isPending` (Server Action pending state)
- Show inline error message below password field on auth failure — never as a toast
- Error position: below the field that caused it, never above the form
- No "show password" toggle in Phase 1 — deferred

### Tenant Switcher (header dropdown)
- Visible only when `role === 'super_admin'` — hidden for tenant_admin/viewer
- Active tenant shown in trigger: `[tenant name] ▾`
- On select: navigate to `/[selected-slug]/dashboard` — no full page reload, use `router.push()`
- Dropdown closes on selection and on outside click (Radix default)
- Maximum 3 items in v1 — no search, no virtualization needed

### User Creation Modal
- "Adicionar usuário" button opens `Dialog`
- Generated temporary password: 16 characters, shown in a `<code>` block after creation
- Password is shown ONCE with a "Copiar senha" button — copy clears after 30 seconds
- Modal does NOT auto-close after user creation — Super Admin must manually close so they can copy the password
- Form reset on close

### Deactivate Tenant
- Uses `AlertDialog` (not `Dialog`) — Radix semantics for destructive confirmation
- Cannot be dismissed by clicking outside (Radix AlertDialog default)

### Logout
- Immediate redirect to `/login` — no confirmation dialog
- Button: icon-only on mobile (`<LogOut size={16}/>`), icon + "Sair" label on desktop (`hidden sm:inline`)

### Loading States
- Tenant list: `Skeleton` rows (3 rows) during initial Server Component load — use `Suspense` boundary
- Form submission: `Button` disabled + spinner icon (use `Loader2` from lucide with `animate-spin`)
- No global loading bar in Phase 1

## Accessibility Contract

- All form inputs have explicit `<label>` elements with `htmlFor` — never placeholder-only labels
- `AlertDialog` used for destructive actions (not `Dialog`) — correct ARIA role semantics
- Logout icon-only button: `aria-label="Sair da conta"` always present
- Color contrast: all text on `bg-card` and `bg-background` meets WCAG AA (shadcn defaults comply)
- Focus ring: Radix/shadcn handles `:focus-visible` ring — do not suppress with `outline-none` without a visible replacement
- Tenant switcher: keyboard navigable (Radix DropdownMenu handles arrow keys + Enter + Escape)
- Temporary password output: `role="status"` on the password reveal container so screen readers announce it

## Responsive Contract

Phase 1 supports desktop-first (Super Admin internal tool). Mobile is graceful degradation only.

| Breakpoint | Login | Header | Tenants table | Modal |
|------------|-------|--------|---------------|-------|
| Mobile (<640px) | Card full-width `px-4` | Wordmark only + icon buttons | Horizontal scroll | Full-screen bottom sheet behavior (Radix Dialog default) |
| Tablet (640–1024px) | Card `max-w-sm` centered | Full header | Full table | Centered modal `max-w-lg` |
| Desktop (>1024px) | Card `max-w-sm` centered | Full header + labels | Full table | Centered modal `max-w-lg` |
