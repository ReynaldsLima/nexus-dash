lib/google-ads/oauth-state.ts (created in Plan 02):
```typescript
interface StatePayload { tenantId: string; tenantSlug: string; customerId: string; nonce: string; iat: number }
export function signState(tenantId: string, tenantSlug: string, customerId: string): string
export function verifyState(state: string): { payload: StatePayload; expired: boolean } | null
// Returns null ONLY on bad signature / malformed / unparseable input (payload is untrustworthy — cannot
//   safely recover tenantSlug).
// Returns { payload, expired: false } when signature valid AND iat within STATE_TTL_MS (fresh).
// Returns { payload, expired: true } when signature valid BUT iat older than STATE_TTL_MS — because the
//   signature checked out, tenantSlug IS trustworthy and can be used to build the D-04 settings redirect
//   (a user who took >10 min on Google's consent/2FA/account-picker screen is the COMMON case, not an attack).
// STATE_TTL_MS = 10 * 60 * 1000; signature = HMAC-SHA256(payloadB64, GOOGLE_OAUTH_STATE_SECRET), base64url
// serialized form: `${payloadB64}.${signature}`
```

app/api/google-ads/connect/route.ts (created in Plan 02):
```typescript
export const runtime = 'nodejs'
export async function GET(req: NextRequest): Promise<Response>
// 401 (JSON) ONLY if no user (no tenant context yet to build a settings redirect — documented limitation);
// on role/scope failure → 3xx redirect to /${tenantSlug}/settings?google_error=forbidden;
// on missing/invalid customerId → 3xx redirect to /${tenantSlug}/settings?google_error=invalid_customer_id;
// on super_admin missing tenant params → redirect ?google_error=missing_tenant;
// on success → 307 redirect to https://accounts.google.com/o/oauth2/v2/auth?...
// (invoked via top-level browser navigation, so every non-success path redirects back to Settings, never raw JSON)
```

export const runtime = 'nodejs'

//   - to / ONLY when the state signature is bad/malformed (no tenant can be safely recovered)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → GET /api/google-ads/connect | Authenticated user initiates OAuth; customerId + (for super_admin) tenant params cross here |
| Google → GET /api/google-ads/callback | Cross-site top-level GET redirect carrying `code`, `state`, or `error` — untrusted until `state` HMAC is verified |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Spoofing/Tampering | OAuth `state` param | mitigate | oauth-state.test.ts asserts verifyState returns null on tampered signature/tampered payload/malformed, and returns `expired:true` (NOT null, payload preserved) on a validly-signed-but-stale state — the executable spec for the HMAC+expiry mitigation (impl in Plan 02) |
| T-07-02 | Elevation of Privilege | GET /connect tenant scope | mitigate | connect-route.test.ts case 7 asserts tenant_admin's authoritative tenantId/tenantSlug come from getClaims(), never from the query string (the query slug is used ONLY to build the error-display redirect, never for authorization) |
| T-07-04 | Information Disclosure | token handling in callback | mitigate | callback-route.test.ts mocks fetch and never asserts on logged secrets; Plan 03 enforces no-logging — this test establishes the behavioral surface without token echo |
| T-07-05 | Tampering (data integrity) | missing refresh_token | mitigate | callback-route.test.ts case 5 asserts a response without refresh_token is a hard error (google_error=no_refresh_token), never a silent partial connect |
</threat_model>
