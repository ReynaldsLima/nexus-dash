# Phase 04 — UI Design Contract: AI Insights

> Visual and interaction contract for Phase 4 (AI Insights). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

This phase is **not greenfield**. `app/[tenant-slug]/insights/page.tsx` is a fully-built mock UI (insight cards, `TYPE_CONFIG` badges, "Gerar Novo Insight" CTA with a fake 2.5s spinner). Per `04-CONTEXT.md` D-10, **this UI is preserved** — only the data source changes (mock → real Supabase query). This UI-SPEC does **not** re-specify the existing `InsightCard`, `TYPE_CONFIG`, or `IMPACT_CONFIG` — they are the established baseline and must be reused verbatim.

This UI-SPEC specifies the **four genuinely new visual/interaction surfaces** this phase introduces:

1. **Streaming card** (D-12) — replaces the current fake "generating placeholder" (`app/[tenant-slug]/insights/page.tsx` lines 190–206) with a real token-by-token streaming display that merges into history on completion.
2. **Anomaly toast** (D-06) — no toast library exists in this project yet (confirmed absent in `04-RESEARCH.md`; Phase 03.1 deliberately avoided one). This contract installs and skins shadcn's official Sonner-based `Toast`.
3. **Sidebar "AI Insights" badge** (D-06) — persistent unread indicator on `components/layout/sidebar-nav.tsx`'s nav link.
4. **Dashboard shortcut card** (D-02) — a second "Analisar agora" entry point on `app/[tenant-slug]/dashboard/page.tsx`.

It also specifies the **empty/error states** for the history list, which the mock never needed (mock data is never empty) but the real `ai_insights` table will be, for a brand-new tenant.

Do not "fix" this to `px-2` or `px-3` — that would create a visible mismatch between the streaming badge and the completed-insight badges sitting directly below it in the same list.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` = `#060608` | Page background behind all cards |
| Secondary (30%) | `var(--card)` = `#0e0e12` / `var(--sidebar)` = `#0e0e12` | Card surfaces (streaming card, dashboard shortcut card, toast body), sidebar background |
| Accent (10%) | `var(--primary)` / `var(--sidebar-primary)` / `var(--ring)` = `#c8ff00` (neon lime) | Reserved exclusively for: (1) the CTA button background ("Analisar agora", both locations — preserved from existing baseline), (2) the active sidebar nav item background, (3) focus rings on all new interactive elements. **Not** used for the streaming card, badge, or toast — those use the semantic colors below to avoid diluting the accent's meaning. |
| Semantic — "in progress" (reused, not new) | `var(--chart-1)` = `#c8ff00`... **correction, see note below** | Streaming card border/badge/cursor |
| Semantic — "alert" (reused, not new) | `var(--chart-5)` = `#ff4757` (dark) / `oklch(0.65 0.20 15)` | Anomaly toast icon/border, sidebar unread badge background |
| Destructive | `var(--destructive)` = `#ff4444` | Not used this phase — no destructive actions introduced (see Deferred Ideas) |

**Correction on "in progress" color:** `var(--chart-1)` in `.dark` is `#c8ff00` (same hex as `--primary` in this theme — both map to the neon lime in dark mode, per `app/globals.css` lines 93/105/106). This is an **existing** convention: the current mock's generating-placeholder icon already uses `style={{ color: 'var(--chart-1)' }}` (`insights/page.tsx` line 198) and blue-ish `--chart-1` is used for "Oportunidade" cards. Since `--chart-1` renders identically to `--primary`'s lime in dark mode, the streaming card will read as accent-colored by default — **this is acceptable and intentional**: the streaming card is the one supplementary state where "this IS the primary action in flight" justifies borrowing the accent hue, exactly as the existing mock already does. Do not introduce a fifth new color for this — reuse `var(--chart-1)` verbatim, matching the preserved baseline.

**Accent reserved for (explicit list, do not extend):**
- CTA button background, both locations ("Analisar agora")
- Active sidebar nav item background (`bg-sidebar-primary`, existing, unchanged)
- Focus-visible rings (`focus-visible:ring-ring`, existing Tailwind convention, unchanged)
- Streaming card (borrowed via `--chart-1`, which equals the accent lime in dark mode — see correction above; this is the sole exception and is inherited from the existing mock, not a new grant)

**New semantic color for this phase:** `var(--chart-5)` (already used in `TYPE_CONFIG.alert` for "Alerta"-type insight cards) is reused for anomaly-alert UI — toast icon color, toast left border, and the sidebar unread-count badge background. This is not a new color; it is the same token the codebase already assigns the meaning "alert" to. Using `--destructive` instead was considered and rejected: `--destructive` is reserved for destructive *actions* (confirmations, deletions) per the Copywriting Contract's own rule, and an anomaly notification is not a destructive action — reusing the already-established "Alerta" chart color keeps the semantic mapping consistent project-wide.

## New Element 1: Streaming Insight Card (D-01/D-12)

**Component to create:** `components/insights/streaming-insight-card.tsx`

**Replaces:** the fake "Generating placeholder" `Card` block in `app/[tenant-slug]/insights/page.tsx` lines 190–206 (currently a centered spinner with static copy on a 2.5s `setTimeout`).

**Position on page:** immediately below the page header, above the history list — same slot the fake placeholder currently occupies (D-12: "A card/area at the top shows the generating text").

### Visual structure (all states share this shell)

```
┌─ rounded-xl border-l-[3px] overflow-hidden (p-5) ─────────────────┐
│ [●pulse] [Sparkles icon]  Analisando campanhas…                   │
│                                                                     │
│ A campanha Shopping mantém ROAS acima da meta nas últimas duas     │
│ semanas, indicando espaço para expansão de orçamento sem perda▊    │  ← streamed text, cursor block blinking at the end
│ de eficiência...                                                   │
└─────────────────────────────────────────────────────────────────────┘
```

- Shell: `rounded-xl border overflow-hidden` — same corner radius and border treatment as `InsightCard`. `borderLeftWidth: 3px`, `borderColor: var(--chart-1)`, `background: oklch(0.60 0.22 258 / 0.08)` — **identical values** to `TYPE_CONFIG.opportunity`'s `borderColor`/`bgColor` (reused, not redesigned).
- Min-height: `min-h-[140px]` to avoid layout jump as text grows from 0 characters upward; no max-height — the card grows naturally with content, matching `InsightCard`'s own unconstrained height.
- Badge (top of card, same shape as `TYPE_CONFIG` badges — `inline-flex items-center gap-1.5 rounded-full px-2.5 py-1 text-xs font-semibold`, background `oklch(0.60 0.22 258 / 0.15)`, color `oklch(0.72 0.16 258)`): contains a small pulsing dot (`size-1.5 rounded-full bg-current animate-pulse`) + `Sparkles` icon (`size-3`) + label text.
- Body text: `text-sm text-muted-foreground leading-relaxed whitespace-pre-wrap` — renders the accumulated `textStream` chunks as they arrive. A blinking cursor (`inline-block w-1.5 h-3.5 ml-0.5 animate-pulse`, `background: var(--chart-1)`) sits at the end of the text while streaming is active; removed once the stream closes.

### States

| State | Trigger | Visual delta from shell |
|-------|---------|--------------------------|
| **Idle** | No generation in flight | Card is not rendered at all — page shows only the CTA button and history list, identical to current baseline when `generating === false`. |
| **Streaming** | `POST /api/insights/generate` response body is being read | Shell as above; badge label "Analisando campanhas…"; cursor blinking at end of text. |
| **Completing** (transient, ~600ms) | Stream closes (`onFinish` fires) | Badge icon swaps `Sparkles` → `CheckCircle2` (reused from `InsightCard`'s recommendation checkmarks), badge color swaps to `var(--chart-3)` tint (`oklch(0.75 0.18 155 / 0.15)` bg / `oklch(0.75 0.18 155)` fg — same green already used for `TYPE_CONFIG.optimization`), label "Análise concluída". Cursor removed. |
| **Merging** | TanStack Query refetches `ai_insights` after the 600ms completing beat | Streaming card unmounts; the newly-fetched insight enters the top of the history list using `animate-in fade-in slide-in-from-top-2 duration-300` (from `tw-animate-css`, already a project dependency — `app/globals.css` line 2 — no new library needed). |
| **Error** | Stream errors, or `fetch` rejects, or HTTP non-2xx before streaming starts | Badge swaps to `AlertTriangle` icon, `var(--chart-5)` tint (matches `TYPE_CONFIG.alert`), label "Falha na análise". Body text replaced with the error copy. A `Button` (`variant="outline"`, `size="sm"`, reusing `components/ui/button.tsx`) with label "Tentar novamente" appears below the body text, right-aligned. Clicking it re-invokes the same generation handler. |

### Interaction contract

- The primary CTA button (`"Analisar agora"`) is `disabled` for the full duration of Streaming/Completing/Merging (existing `disabled={generating}` pattern preserved) — prevents a second concurrent generation.
- No cancel button in v1 (not requested in CONTEXT.md; out of scope).
- Streaming card has no click affordance — it's a passive display; the only interactive elements inside it are the retry button (error state only).

| CSS variable overrides (per shadcn Sonner's supported custom properties) | `--normal-bg: var(--card)`, `--normal-border: var(--border)`, `--normal-text: var(--foreground)` — makes the toast surface match this app's card color instead of Sonner's default white/gray |

```
┌───────────────────────────────────────────┐
│ [⚠ chart-5]  ROAS caiu 24% — Shopping BF   │
│              Nas últimas 24 horas em       │
│              Google Ads. Veja a análise    │
│              completa.                     │
│                                    [Ver Insights] │
└───────────────────────────────────────────┘
```

- Icon: `AlertTriangle` (reused from `TYPE_CONFIG.alert`'s icon), color `var(--chart-5)`.

### Interaction contract

- Fired on every Supabase Realtime `INSERT` event on `anomaly_alerts` (per `04-RESEARCH.md`'s `useAnomalyAlerts` hook pattern) — one toast per anomaly row, not batched/deduplicated in v1 (matches D-05's per-campaign anomaly granularity).
- Clicking the toast body (not just the action button) also navigates to `/${tenantSlug}/insights` — standard toast-as-link affordance, `cursor-pointer` on the whole toast.
- Toast auto-dismisses after 8000ms if not interacted with; does not require the sidebar badge to also be cleared (they are independent — see Element 3).

## New Element 3: Sidebar "AI Insights" Unread Badge (D-06)

**File to modify:** `components/layout/sidebar-nav.tsx`

**Current structure (line 19–34):** `NavLink` renders `<Icon /> {label}` in a flex row with no trailing slot. This contract adds a trailing badge slot, active only for the `insights` nav item.

### Visual spec

```tsx
<Link className="flex items-center gap-3 px-3 py-2 rounded-md text-sm font-medium …">
  <Icon className="size-4 shrink-0" aria-hidden="true" />
  {label}
  {badgeCount > 0 && (
    <span
      className="ml-auto inline-flex h-5 min-w-5 items-center justify-center rounded-full px-1 text-[10px] font-semibold"
      style={{ background: 'var(--chart-5)', color: 'white' }}
      aria-label={`${badgeCount} alertas de anomalia não visualizados`}
    >
      {badgeCount > 9 ? '9+' : badgeCount}
    </span>
  )}
</Link>
```

- Shape: circular pill, `h-5 min-w-5` (20px), matches the existing `Badge` component's own height convention (`components/ui/badge.tsx` line 8: `h-5`) — reuses the project's badge sizing token rather than inventing a new one.
- Color: `var(--chart-5)` background, white text — the same "alert" semantic established above, distinct from the lime accent (never use `--primary`/`--chart-1` for this badge — that hue is reserved for "in progress"/CTA, not "needs attention").
- Position: `ml-auto` inside the existing flex row — pushes the badge to the far right of the nav item, standard sidebar-badge convention, no absolute positioning needed since `NavLink` is already a flex container.
- **Hidden entirely when count is 0** — never render a "0" badge. This must be an `{count > 0 && …}` conditional, not a badge with `0` inside it.
- Overflow: counts above 9 display as `"9+"` rather than wrapping or truncating the pill.

### Clear-on-visit behavior

- The badge count is backed by a shared client-side store (recommend `lib/stores/anomaly-alerts.ts`, a plain Zustand `create()` singleton — same pattern as `lib/stores/date-range.ts`, no Provider needed) rather than a hook re-instantiated independently inside `SidebarNav` and wherever the toast is fired. This avoids two separate Supabase Realtime subscriptions for the same table.
- `SidebarNav` already has `pathname` via `usePathname()` (line 4/37). Add: `useEffect(() => { if (pathname.startsWith(`/${slug}/insights`)) clearUnread() }, [pathname])` — clears the badge the moment the Super Admin navigates to the Insights page, matching D-06's "until the Super Admin visits the page."
- Clearing the badge does **not** delete the underlying `anomaly_alerts` rows or mark them as read in the database in v1 — it is a client-side unread counter only, reset on every visit (matches Deferred Ideas: "Manual alert acknowledgment / dismiss workflow" is explicitly out of scope — this is a lighter-weight, visit-based reset, not an acknowledgment system).
