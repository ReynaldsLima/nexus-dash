    1. Read query params: `code`, `state`, `error` from `req.nextUrl.searchParams`.
    2. Verify state FIRST (it carries the authoritative tenant binding — this is the CSRF/replay defense, T-07-01):
       ```typescript
       const rawState = req.nextUrl.searchParams.get('state') ?? ''
       const payload = verifyState(rawState)
       if (!payload) {
         // State unverifiable → we cannot trust any tenant identity, so we cannot build a tenant-scoped
         // redirect. Send to root. Never write anything.
         return NextResponse.redirect(new URL('/', req.nextUrl.origin))
       }
       const { tenantId, tenantSlug, customerId } = payload
       ```
    3. Helper to build the settings redirect used by every subsequent exit:
       ```typescript
       function settingsRedirect(errCode?: string) {
         const url = new URL(`/${tenantSlug}/settings`, req.nextUrl.origin)
         if (errCode) url.searchParams.set('google_error', errCode)
         else url.searchParams.set('google_connected', '1')
         return NextResponse.redirect(url)
       }
       ```
    4. If Google returned an `error` param (consent denied etc.), redirect with it (D-04):
       ```typescript
       const googleError = req.nextUrl.searchParams.get('error')
       if (googleError) return settingsRedirect(googleError)   // e.g. access_denied
       ```
    5. Require `code`:
       ```typescript
       const code = req.nextUrl.searchParams.get('code')
       if (!code) return settingsRedirect('missing_code')
       ```
    6. Exchange the code (raw fetch; redirect_uri MUST equal the connect route's — same `req.nextUrl.origin` source, Pitfall 1):
       ```typescript
       const redirectUri = `${req.nextUrl.origin}/api/google-ads/callback`
       let tokenRes: Response
       try {
         tokenRes = await fetch('https://oauth2.googleapis.com/token', {
           method: 'POST',
           headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
           body: new URLSearchParams({
             code,
             client_id: process.env.GOOGLE_ADS_CLIENT_ID ?? '',
             client_secret: process.env.GOOGLE_ADS_CLIENT_SECRET ?? '',
             redirect_uri: redirectUri,
             grant_type: 'authorization_code',
           }),
         })
       } catch {
         return settingsRedirect('token_exchange_failed')
       }
       if (!tokenRes.ok) return settingsRedirect('token_exchange_failed')   // never log the body (Pitfall 5)
       const tokens = (await tokenRes.json()) as { access_token?: string; refresh_token?: string; expires_in?: number }
       ```
    7. Missing refresh_token is a HARD error (Pitfall 2 / T-07-05 — never silently persist):
       ```typescript
       if (!tokens.refresh_token) return settingsRedirect('no_refresh_token')
       ```
    8. Write refresh_token to Vault + upsert ad_accounts (service role — mirror Meta):
       ```typescript
       const service = createServiceClient()
       const secretName = `google_ads_token_${tenantId}`
       const { data: secretId, error: vaultErr } = await service.rpc('create_or_update_vault_secret', { p_name: secretName, p_secret: tokens.refresh_token })
       if (vaultErr || !secretId) {
         console.error('[google-ads/callback] Vault write failed:', vaultErr?.message)   // message only, never the token
         return settingsRedirect('vault_write_failed')
       }
       const { error: upsertErr } = await service.from('ad_accounts').upsert(
         { tenant_id: tenantId, channel: 'google_ads', account_id: customerId, vault_secret_id: secretId as string, active: true },
         { onConflict: 'tenant_id,channel' })
       if (upsertErr) {
         console.error('[google-ads/callback] ad_accounts upsert failed:', upsertErr.message)
         return settingsRedirect('save_failed')
       }
       ```
    9. Success: `return settingsRedirect()` (sets `google_connected=1`).

    Do NOT write `tokens.refresh_token`/`access_token` or `code` into `ad_accounts.refresh_token` (legacy plaintext column — RESEARCH anti-pattern) or into any log line. Only `vault_secret_id` is stored.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Spoofing/Tampering | state verification | mitigate | verifyState (HMAC + 10-min expiry) runs before any trust; unverifiable state redirects to `/` with zero side effects (callback-route.test.ts case 1) |
| T-07-03 | Tampering | auth code interception/replay | mitigate | Google enforces single-use, short-lived codes; this route never logs the `code` and exchanges it immediately server-side over HTTPS |
| T-07-04 | Information Disclosure | token/code logging | mitigate | No console.log anywhere; console.error logs only `err.message`/fixed strings; token body of a failed exchange is never logged (Pitfall 5) |
| T-07-05 | Tampering (data integrity) | missing refresh_token | mitigate | A response without refresh_token → `google_error=no_refresh_token`, no Vault write, no upsert (callback-route.test.ts case 5) |
| T-07-07 | Information Disclosure | plaintext credential at rest | mitigate | refresh_token stored ONLY via Vault (create_or_update_vault_secret); the legacy `ad_accounts.refresh_token` column is never written (grep-verified) |
