## Plan 05-02

- **CRITICAL — live Auth Hook is wired to an unrelated Edge Function, not `public.custom_access_token_hook`:**
  - Discovered while filling `tests/agency-rls.test.ts`: signing in as a freshly created agency-member test user produced a JWT with `app_metadata = {"plan":"trial","provider":"email","providers":["email"],"role":"visualizador","slug":null,"tenant_id":null,"trial_ends_at":null}` — none of which matches this project's own `custom_access_token_hook` Postgres function (migrations 0005/0019).
  - Root cause confirmed via the Supabase Management API (`GET /v1/projects/rvkkvjitfddtbdpkupok/config/auth`): `hook_custom_access_token_enabled: true`, `hook_custom_access_token_uri: https://rvkkvjitfddtbdpkupok.supabase.co/functions/v1/custom-access-token` — an HTTP hook pointing at a deployed Edge Function (`custom-access-token`, version 2, last updated 2026-07-05), NOT a `pg-functions://...` URI pointing at the Postgres function.
  - The Edge Function's source (`supabase functions download custom-access-token`, inspected then deleted — not part of this repo's tracked `supabase/functions/`) does not query `agency_users` or `tenant_users` at all. It only echoes whatever `app_metadata.tenant_id`/`role`/`slug` a user already has (querying `tenants.trial_ends_at`/`plan` — columns that DO NOT EXIST in this project's live `tenants` table, so that lookup silently no-ops), and additionally writes the tenant slug back under the key `slug`, not `tenant_slug` — which `app/[tenant-slug]/layout.tsx` actually reads (`user.app_metadata?.tenant_slug`). This means `tokenSlug` is likely `null` for every real signed-in user in the deployed app today.
  - **Impact:** the entire Postgres-hook-based architecture designed in Phase 1 (D-13/D-14) and extended in Phase 5 (agency role/agency_id injection) is dead code in production as currently configured. Nothing in `custom_access_token_hook` ever fires for real user sign-ins. Agency members will NOT receive `role='agency'`/`agency_id` on sign-in until the Auth Hook selection is switched back to the Postgres function.
  - **Not fixed in this plan** (Rule 4 — switching a live project's Auth Hook wiring affects every authenticated session across the whole app, not just this plan's files; requires explicit user decision, likely via Supabase Dashboard → Authentication → Hooks → Custom Access Token → select `pg-functions://postgres/public/custom_access_token_hook`, or updating the Edge Function itself to replicate the agency_users/tenant_users lookup — an architectural choice for the user to make).
  - **Workaround used for this plan's own tests:** `tests/agency-rls.test.ts` presets `app_metadata: { role: 'agency', agency_id }` directly at `admin.createUser()` time (mirrors the existing `tests/integration/sync-jobs-rls.test.ts` pattern for `tenant_admin`), which correctly exercises the `_agency_select` RLS policies (this plan's actual deliverable) independent of the hook-wiring bug.
  - **Recommend:** a dedicated quick-fix/decision before Plan 04 (routing) or Plan 07 (agency landing page) — those plans assume a real sign-in produces a JWT with `role='agency'`/`agency_id` populated, which will NOT happen until this is resolved.
