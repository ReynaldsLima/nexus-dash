  <what-built>Verification that N8N_ENCRYPTION_KEY survives a VPS restart, and that execution data pruning is configured to prevent disk bloat on the 2 GB VPS.</what-built>
  <how-to-verify>
SSH into the Hostinger VPS. Run these checks in sequence.

**1. Verify N8N_ENCRYPTION_KEY is persisted to disk:**
```bash
# For systemd — check the service file or EnvironmentFile:
systemctl cat n8n | grep -i ENCRYPTION_KEY

# For pm2 — check the ecosystem config:
cat ~/ecosystem.config.js 2>/dev/null | grep ENCRYPTION_KEY

# For a flat .env file:

grep N8N_ENCRYPTION_KEY /etc/n8n/.env 2>/dev/null
```

Expected: A non-empty 64-character hex string. **If the key is NOT found in any of these files** — it is only in memory and will be lost on next restart. In that case: find the currently-running value with `cat /proc/$(pgrep node)/environ | tr '\0' '\n' | grep ENCRYPTION_KEY`, then write it to the correct persistent location before rebooting.

**CRITICAL (D-02):** Do NOT generate a new key. An existing key is already set and credentials are encrypted with it. Replacing the key renders all stored credentials unreadable.

**2. Add execution pruning env vars if not already set:**

Check existing configuration:

```bash
EXECUTIONS_DATA_SAVE_ON_SUCCESS=none
EXECUTIONS_DATA_MAX_AGE=168
EXECUTIONS_DATA_PRUNE_MAX_COUNT=5000
NODE_OPTIONS=--max-old-space-size=1024
```

After editing, reload N8N:
```bash
systemctl restart n8n
# or: pm2 restart n8n
```
